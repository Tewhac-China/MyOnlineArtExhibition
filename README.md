# 笔触的来处 · 线上展厅

三组 AI 辅助绘画作品的静态展示站。无框架、无 CDN、无追踪，直接用浏览器打开 `index.html` 即可。

在线访问：<https://tewhac-china.github.io/MyOnlineArtExhibition/>

```
index.html            首页（展名 / 三个系列 / 两种范式 / 介入维度说明 / 字体与来源说明）
comfyui.html          01 画风所寄 —— MyFavourite_HighQuality（142 张，扩散模型，按主题 / 按版本双视图）
collage.html          02 千禧迷思 —— 拼贴画成品（6 帧，程序化合成）
backgrounds.html      03 东方风背景图 —— 五个系列 118 张（程序化合成；仿东方Project封面背景设计）

assets/css/style.css  样式（含字体约定与竖屏适配）
assets/js/app.js      共用交互（顶栏 / 进场 / 展墙 / 筛选 / 图片查看器）
assets/data/*.js      window.__DATA_* 数据（由 build_site.py 产生，勿手改；ai 字段=该张标识文案，空则前端不画条）
assets/img/<coll>/    t_NNN.jpg 缩略图（640 长边，q70）· l_NNN.jpg 灯箱档（原分辨率 q80，长边>3000 限到 3000）· f_NNN.webp 原图档（原始分辨率 + 原始编码）
assets/favicon.svg    站点图标（一笔金色笔触）；另有 32px PNG 与 180px apple-touch-icon
assets/fonts/         标题字体子集 kinghwa-sub.woff2（714KB，首选）+ .ttf（老浏览器兜底）
build/build_site.py   扫描来源目录 → 生成图片与数据
build/subset_fonts.py 把标题字体裁成本站用到的字
```

## 字体约定

| 位置 | 字体 |
|---|---|
| 所有标题（展名 / 系列名 / 分组名 / 作品名） | 京华老宋体（KingHwaOldSong） |
| 全站说明正文 | 思源黑体（Source Han Sans / Noto Sans SC） |
| 提示词、数值、编号 | 等宽字体（Cascadia Mono / Consolas） |

京华老宋体是 GB 字库，简体字形齐全（4 万余字），与拼贴画成片所用字体同源。
华康金文体曾是背景页的标题字体，但它是 Big5 字库，缺简体字形（纯 / 这 / 说 / 时 / 为 / 对 / 开 / 图 / 标 / 记 / 题 / 场 等），
在简体正文下会逐字回退成别的字体，因此不再使用。

`@font-face` 先试 `local()`（本机已装则零下载），失败才回落到 `assets/fonts/` 的子集。
子集脚本扫描 HTML、数据文件、**`assets/js/app.js`**（界面文案在 JS 里），
以及 CSS 里 `content:""` 写出的文字 —— 漏掉任何一处，
像灯箱分组标签「所在 · 」这种只在样式里出现的字就会静默回退成别的字体。

**手机字体不对的根因就是这个**：缺字是逐字回退、不报错，
装了本机字体的机器（作者本机）完全看不出异常，只有在没有该字体的手机上才露馅。
所以 `build/subset_fonts.py` 裁完会回读 cmap 逐字核对，缺一个字就 `exit 1`。
改完文案/新增作品后必须重跑一次，再提交 `assets/fonts/` 下的两份文件。

## 图片查看器（灯箱）

鼠标与触摸双套操作，均为原生 Pointer Events 实现：

| 操作 | 鼠标 | 触摸 |
|---|---|---|
| 缩放 | 滚轮 / `+` `-` 按钮 / 键盘 `+` `-` | 双指捏合 |
| 平移 | 按住拖动 | 单指拖动（放大后） |
| 快速放大 | 双击 | 双击 |
| 适应窗口 | `⤢` 按钮 / 点击百分比 / 键盘 `0` | 同左 |
| 1:1 原始像素 | `1:1` 按钮（灯箱档被限幅时自动先取原图再放大） | 同左 |
| 显示原图 | `原图` 按钮 / 键盘 `O`（再按一次退回灯箱档） | `原图` 按钮 |
| 切换图片 | `‹` `›` / 键盘方向键 / 未放大时横向拖动 | 左右按钮 / 未放大时横滑 |
| 下载原图 | `↓` 按钮 / 键盘 `D` | `↓` 按钮 |
| 全屏 | `⛶` 按钮 / 键盘 `F` | `⛶` 按钮（iOS Safari 不支持元素全屏，会静默跳过） |
| 关闭 | `Esc` / 点空白处 / `✕` | 点空白处 / `✕` |
| 收起信息栏 | `ⓘ` 按钮 / 键盘 `I`（小屏可用它换更大画布） | 同左 |

**切换的范围是「当前看得见的整条序列」，不是单个子主题。** 按主题视图里从「舞台」最后一张
继续往右，会进入「废墟」第一张；按版本视图跨的是轮次；背景页跨的是五个系列。
计数（`16 / 142`）与首尾循环都按这条全局序列算，信息栏会标出当前这张属于哪一组
（只有一组时不标）。筛成单一分组时，序列自然收缩为那一组 —— 筛选是显式意图，不越过它。

缩放以指针位置为锚点，上限是原生的 200%，平移带边界钳制，不会把图拖丢。

**百分比按原生像素算**：100% = 一个图像像素对一个 CSS 像素（跟看图软件一致），
「适应窗口」那一档会显示成 8% 之类的数字 —— 8K 图缩进 1440×900 的窗口本来就只有 7%–8%。
`1:1` 与双击都直接切到 100%，所以在 8K 作品上看到的是真正的原始像素。
横滑的判定是：未放大、水平位移 > 60px 且明显大于垂直位移（> 1.6×），
所以小幅拖动仍是「点空白关闭」，斜着拖也不会误切。

**分辨率策略**：三档各有各的付带宽的人。展墙只付缩略图（每张约 20KB，滚动到才加载）；
点开灯箱付灯箱档 —— 它就是原分辨率 JPEG（q80），只有长边超过 3000 的超大画幅才限到 3000，
所以「放大看清楚」不再需要等第二张图；**原图档（原始分辨率 + 原始 WebP 编码）不再自动接管**，
只在按 `原图` / `O`、或按 `1:1` 而灯箱档确实被限幅时才请求。
改这一条的原因很实际：一张 8K 原图是 3–5 MB，让每次翻页的人都替它付带宽，
在低带宽源站（5 Mbps 一档）上就是 8–9 秒的空白。
信息栏那一行现在说真话：`原图 5312 × 8704 · 当前 1832 × 3000，按 O 取原图` → `载入原图…` → `原图 · 5312 × 8704`。
`1:1` 仍按**原始像素**计算（读的是原图尺寸，不是当前位图尺寸）——
灯箱档被限幅时它会先把原图取回来再放大，而不是把 3000 的位图拉成 5312 却显示 100%。

**预取**：左右两张的缩略图立刻预取（几十 KB，翻页至少不空白）；
灯箱档等用户停下来 650ms 后才预取，且连着翻页时不抢带宽；原图档永不预取。

**载入反馈**：灯箱档没到手时舞台不会留一片黑 —— 先用已经躺在页面里的缩略图按最终版位铺开、
压暗并模糊成占位（版位按「灯箱档尺寸 + 它带的黑条高」算，所以图到位时不会「长大一圈」），
同时浮出一块细边框小面板（金色弧线 + `载入中`）。提示延迟 70–120ms 才出现，
所以预取命中时根本看不到它；滑到下一张时旧画面会被压暗而不是干等着。

**下载**拿到的也是这一张的 `f_` 档（原始分辨率、原始编码），文件名沿用源目录的原始输出名
（`v35_port_00001_.webp`），后缀按实际发布那一档的格式给，方便和本地图库对照。
带 AI 标识的那一组下载时由前端现场合成黑条（见「AI 标识」），所以导出件不带 EXIF；
不带标识的组直接给原文件，一次重编码都不发生。原图档不重新编码成 PNG
（那会多一次损失，也会把 8K 图撑到 40MB+）。

## 重新生成

源目录路径写在 `build/sources.local.json`（含本机信息，已在 `.gitignore` 内，不入库）；
新克隆仓库时先 `cp build/sources.example.json build/sources.local.json` 再填三个目录。

图片有增减时：

```bash
# 0) 想调三档参数时先用探针：只重出几张，量字节、量耗时、裁一条黑条出来看，
#    产物落在 build/probe/，不碰正式目录、不写 manifest
python build/build_site.py probe 2

# 1) 重新扫描来源目录，重建三档与数据（没变的图会跳过）
python build/build_site.py            # 或 comfy / collage / bg 只跑一组

# 2) 若新增了标题文字，重裁字体子集
python build/subset_fonts.py
```

**源目录增删之后必须重跑一次**，因为图片按「文件名排序后的序号」命名（`f_007.webp`）：
删掉一张，后面所有序号都会往前挪一格。脚本用 `assets/img/<coll>/manifest.json`
记录「序号 → 源文件名」，序号对不上就强制重编码，不会把旧图留在新序号上（那样既不报错、
图又是错的）。序号超出现有条数的产物会被自动清掉。

**接了 CDN 之后，这条挪序号的代价会放大很多**：文件名一变，全部 URL 跟着变，
边缘缓存整体失效，200 MB 得从源站重新喂一遍 —— 5 Mbps 源站就是约 320 秒满载，
这期间所有访客都在等那根小水管。所以真上 CDN 之后，图目录尽量只追加、不重排；
非要删，就接受一次全量回源，并在发布后分批预热热门图，别在高峰期刷缓存。

依赖：`pillow`、`numpy`、`fonttools`，可选 `opencc`（用于把展示用标题转成简体；未安装时保留原文）。

三档图片的体积（2026-11-04 全量重建后实测，按引用逐条 HEAD 统计）：
缩略图 640 长边 q70，均值约 42KB，266 张合计 11.2 MB ·
灯箱档原分辨率 q80，266 张合计 98.1 MB（2048×1408 一张约 293KB；8K 限到 3000 后约 0.8–1.0 MB）·
原图档 162 张合计 145.9 MB（0.3–4.2MB 一张，8K 拼贴与 8000px 排布最大）。全站图片 255.2 MB。

**别把 11.2 MB 当成访客要付的数**：展墙是懒加载，1440×900 一屏约 15 张 ≈ 0.6 MB，
5 Mbps 源站约 1 秒；灯箱档一次一张；原图档只在显式动作时才发生。
同尺寸下 JPEG 比 WebP 贵约 1.5–1.7 倍（640 长边样本实测：jpg q70 37KB / jpg q64 32KB /
webp q76 24KB / webp q70 21KB）—— 要压展墙总量就降 THUMB_Q，或把 THUMB_EXT 改回 "webp"
（编码器现在按后缀走，改常量不会写出内容对不上扩展名的文件）。

## AI 标识

《人工智能生成合成内容标识办法》2025-09-01 施行，配套 GB 45438-2025 规定图片的显式标识
要用文字、位于图片的边或角，要素里同时含「AI/人工智能」与「生成/合成」；提供下载导出时
文件本身也要带显式标识；元数据里另加隐式标识。本站的做法是**标识不进图片文件**：

- **显式（展示）**：灯箱里由 `app.js` 的 `syncMark()` 在画面下缘贴一条 DOM 黑条
  （样式在 `style.css` 的 `.lb__mark`），左侧「AI 辅助生成 · 扩散模型」加粗小字，
  右侧内容编号。它按当前缩放平移量算位置、绕自身顶边缩放，所以始终贴着画面底缘；
  过渡时长与 `.lb__img` 的 `is-anim` / `is-quick` / `is-slide` 三态一一对齐 ——
  对不齐的话滑动时条会和画面脱开，这是这套做法唯一的技术难点。
  **条跟着画面走，不跟着档位走**：灯箱档、按「原图」/`O` 换上的 `f_` 档、1:1、全屏、
  放大平移，画的是同一个 DOM 元素，所以显示原图时黑条不会消失。
- **给条留的地方**：`.lb` 上的 `--mark-pad`（带标识时 `56px`，手机断点 `96px`，无标识 `0`）
  同时加进舞台的 `padding-bottom` 并从图片限高里扣掉，于是画面底缘、黑条、工具条各占其位。
  留白走变量而不是再写一条 `100svh` 算术：灯箱在窄屏是「舞台 + 信息面板」上下两栏，
  限高本来就是按 `svh` 分断点调的，用一条 viewport 算术去盖它会反过来把条裁掉。
- **量不到就不画**：换 `src` 的那一帧 `clientWidth` 可能是 0，`measure()` 会兜成 1，
  于是条会塌成 1px 宽 —— 看上去就是「显示原图时黑条没了」。`syncMark()` 因此拒绝用
  废量测改几何：画过就保持原样（新位图 `load` 时再量一次），没画过就宁可不画、
  补测量且最多 8 次（视口尺寸为 0 时不会留下自转的定时器）。
- **显式（交付）**：点下载时前端用 canvas 现场合成「画面 + 黑条」再导出
  （优先 WebP，不支持就退 JPEG），文件名沿用源目录的原始输出名。
  画幅超过 24M 像素时 canvas 画不动，退回原始文件并在信息栏写明「无标识条」。
- **隐式**：`l_` / `f_` 的 EXIF `ImageDescription` 写 属性信息 / 服务提供者编码 / 内容编号，
  `Software` 写管线名 —— 只动元数据，不动像素，`EMBED_META = False` 可整体关掉。
  注意 **canvas 合成的导出件不带 EXIF**（浏览器画不出元数据），
  要连隐式标识一起交付，就直接取 `f_` 文件本身。
- **只标该标的**：`AI_LABEL` 里只有 `comfy`（画风所寄，扩散模型）有标识；
  `collage` 与 `bg` 是程序化合成，加了就是错误标注 —— 既不画条也不写元数据，
  下载直接给原始文件，一次重编码都不发生。
- 展墙缩略图不画条：一格约 290 CSS 像素，小字不可读只会变脏；
  页面级说明在 index 的「关于这个展厅」。
- 条高 = 画面显示高 × 4.5%（最低 22px）、字号 = 条高 × 52%（最低 11px）、
  配色走 `--accent` —— 三个数都在 `syncMark()` 与 `.lb__mark` 里，
  改完不用重编码任何图片。标识从构建端挪到前端，省下来的最大一笔就是这个。
- 成品卡那批（`build_full_copy`）按字节复制，**不重编码**（8000×8000 再压一次就是
  第二代损失）；复制前探一眼源文件，若带 EXIF/XMP 就当场报错只报文件名 ——
  相机与工具链元数据里常藏本机路径，宁可停下也不悄悄发出去。

## 隐私约定

站点发布到公网前已做处理：**不包含任何本地路径**。

- 数据文件里不含源目录的绝对路径（构建时就不写入）；
- 页面页脚只描述作品，不列目录；
- 展示用的文件名字段只保留原始文件名，不含盘符或目录层级；
- 构建脚本也不含本机路径 —— 源目录读自 `build/sources.local.json`，该文件已被 gitignore。

如需再确认，可执行：`grep -rn "[A-Z]:" *.html assets/data/*.js`，应无命中。

## 部署到 GitHub Pages

仓库设置里 Pages 来源为 `Deploy from a branch` → 分支 `main` / 目录 `/`。
站点根目录有 `.nojekyll`，Pages 会原样静态服务，不走 Jekyll 构建（否则下划线开头的文件会被跳过）。

改完内容 `git push` 即自动重新发布，通常一分钟内生效。所有资源引用都是相对路径，
所以子路径 `/<仓库名>/` 与自定义域名都能直接工作，无需配置 baseurl。

## 一个必须说清楚的区别

三个系列里只有「画风所寄」是扩散模型生成的。「千禧迷思」与「东方风背景图」
不含任何扩散模型输出 —— 它们是 Pillow / NumPy 写成的程序化渲染管线，
素材来自照片库与原封面色板。页面在两处都明确标注了这一点。
